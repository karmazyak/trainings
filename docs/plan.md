# Plan: Arete Bot v2 — Переосмысление под реальную жизнь

## Задача
Переделать фитнес-бота из "ригидного планировщика" в "умного адаптивного тренера", который учитывает реальную жизнь: смешанные тренировки, еда на днях рождения, прогресс весов, понятная техника с объяснениями, и онбординг который даёт ценность сразу.

## Тип
продукт / редизайн

## Текущие проблемы (детально)

### P1: Один training_style на всё
- Модель User.training_style = "gym" | "home" | "crossfit" | "running"
- В system prompt trainer agent жёстко запрещает упражнения из других стилей
- Реальность: человек ходит в зал 3 раза, бегает 1 раз, играет в футбол по выходным

### P2: Нет трекинга прогресса
- TrainingSession хранит workout_content (текст), но нет структурированных данных
- Нет модели Exercise с весами, подходами, повторениями
- Нет целей типа "жим лёжа 100кг к июню"
- Нет истории "в прошлый раз было 80кг x 5, сегодня попробуй 82.5кг x 5"

### P3: Онбординг не даёт ценности
- 6 шагов сбора данных → микротренировка (которую никто не делает)
- Нет объяснения что бот умеет и зачем
- Нет "aha moment" до регистрации

### P4: Питание оторвано от жизни
- Генерируем жёсткий рацион на неделю
- Нет "я на дне рождения, что выбрать?"
- Нет "я в магазине, помоги выбрать продукт"
- Нет адаптации "сегодня не тренировался, пересчитай калории"

### P5: Техника без объяснений
- Даём упражнения, но не объясняем ключевые точки
- Видео-анализ есть, но это reactive, не proactive
- Нет подводящих упражнений для новичков
- Не рассказано что за источники (NSCA, доказательная медицина)

### P6: Ценность RAG скрыта
- Юзер не знает что советы основаны на NSCA, Гарварде и тд
- Нет ссылок на источники в ответах
- Нет объяснения "почему именно так"

## Результаты / Шаг 1: Продуктовое переосмысление

### Ключевой инсайт

Arete v1 — это **генератор планов**. Arete v2 должен стать **адаптивным тренером**, который живёт в контексте реальной жизни пользователя. Разница: генератор даёт план и забывает, тренер сопровождает каждый день и реагирует на ситуации.

---

### 1. Новая модель тренировок: "Моя неделя" (Multi-Activity Schedule)

**Концепция:** Вместо одного `training_style` — понедельная карта активностей. Каждый день = слот с типом активности.

**Типы активностей:**
- 🏋️ Зал (силовые)
- 🏠 Дома (bodyweight)
- 🏃 Бег / кардио
- 🧘 Йога / растяжка
- ⚽ Спорт (футбол, баскетбол, плавание, etc.)
- 😴 Отдых

**Как собирать на онбординге (упрощённо):**
1. Спросить "Сколько раз в неделю тренируешься?" → "3"
2. Показать шаблоны:
   - "🏋️ Зал 3 раза" → Пн/Ср/Пт зал
   - "🏋️ Зал + 🏃 Бег" → Пн/Чт зал + Вт бег
   - "Настроить самому"
3. Если "самому" — быстрый выбор дней + тип для каждого
4. После онбординга можно менять в любой момент

**Как это меняет agent prompt:**
Вместо жёсткого "ЕСЛИ стиль = gym" → промпт получает полное расписание:
```
Расписание пользователя:
Пн — Зал (силовые), Вт — Бег, Ср — Отдых, Чт — Зал (силовые), Пт — Йога, Сб — Футбол, Вс — Отдых
```
Тренер генерирует план ПОД КАЖДЫЙ день адекватно типу.

**UX в Telegram:**
```
📅 Настроить неделю

Пн: [🏋️ Зал] [🏠 Дома] [🏃 Бег] [🧘 Йога] [⚽ Спорт] [😴 Отдых]
Вт: [🏋️ Зал] [🏠 Дома] [🏃 Бег] [🧘 Йога] [⚽ Спорт] [😴 Отдых]
...
```
Нажал кнопку — выбрал тип для дня. Можно менять в профиле.

### 2. Система прогресса (Exercise Logging + Goals)

**Концепция:** Бот знает историю весов и подсказывает прогрессию. Прогресс — главная мотивация.

**Два режима логирования:**

**A) Быстрый лог после тренировки (push):**
После "✅ Выполнил" тренировку:
```
💪 Записать результаты?

Жим лёжа:
Прошлый раз: 80кг × 5 × 4
[Так же] [+2.5кг] [Другое]

Приседания:
Прошлый раз: 100кг × 5 × 3
[Так же] [+5кг] [Другое]
```
Максимум 2 нажатия на упражнение. "Так же" = копировать прошлый. "+2.5кг" = автоматическая прогрессия. "Другое" = ввод вручную.

**B) Ручной лог (pull):**
Кнопка "📝 Записать подход" в меню. Flow:
```
📝 Выбери упражнение:
[Жим лёжа] [Приседания] [Становая]
[Жим стоя] [Подтягивания] [Другое]

→ Жим лёжа
Вес (кг)? → 82.5
Повторения? → 5
Подходы? → 4

✅ Записано: Жим лёжа 82.5кг × 5 × 4
Прогресс: +2.5кг с прошлой недели 📈
```

**Цели:**
Кнопка "🎯 Мои цели" в меню:
```
🎯 Установить цель

[💪 Жим лёжа → 100кг]  — сейчас 80кг, осталось +20кг
[🦵 Присед → 140кг]    — сейчас 110кг
[➕ Новая цель]

Прогноз: при текущем темпе ≈ 8 недель до 100кг жима 📊
```

**Как бот использует данные:**
- При генерации плана trainer видит: "Жим лёжа: последние 4 тренировки — 75, 77.5, 80, 80кг. Рекомендуй 82.5кг."
- Прогрессия в плане автоматическая — не общие "4x8", а конкретные "82.5кг × 5 × 4"
- Если вес стагнирует 3+ недели — предложить deload или смену программы

### 3. Новый онбординг (3 шага → aha moment)

**Проблема v1:** 6 шагов сбора данных → микротренировка. Юзер не понимает зачем и уходит.

**Новый flow:**

**Экран 1: Value prop + "попробуй бесплатно"**
```
🏛 Arete — AI-тренер на основе спортивной науки

Что умею:
• Персональные тренировки под твой график
• Трекинг прогресса и весов
• Советы по питанию в любой ситуации
• Техника упражнений с объяснением "почему"

📚 Все рекомендации основаны на NSCA, Harvard Health,
   и 15+ научных источниках

Попробуй прямо сейчас — задай любой вопрос:
```
→ Юзер пишет вопрос в свободной форме ("как накачать грудь?", "что съесть перед тренировкой?")
→ Бот отвечает СРАЗУ, используя RAG, со ссылкой на источник
→ **Это и есть aha moment — юзер видит качество ответа ДО регистрации**

**Экран 2: Быстрый профиль (1 экран)**
```
Понравилось? Давай настрою под тебя!

🎯 Цель: [Похудеть] [Масса] [Форма] [Сила]
💪 Уровень: [Новичок] [Средний] [Продвинутый]
```
Два нажатия — готово. Пол, рост, вес — progressive profiling (спросим когда понадобится для расчёта КБЖУ).

**Экран 3: Моя неделя**
```
Последний шаг — как выглядит твоя неделя?

Шаблоны:
[🏋️ Зал 3 раза/нед]
[🏋️ Зал + 🏃 Бег]
[🏠 Дома]
[🧘 Йога + бег]
[⚙️ Настроить]
```
→ Выбрал шаблон → бот сразу генерирует план на неделю

**Итого: 3 шага вместо 6, aha moment на первом экране.**

### 4. Гибкое питание: "Ситуативный помощник"

**Концепция:** Питание не план на неделю, а контекстный помощник. Два режима:

**A) План питания (как раньше, но умнее):**
- Адаптируется к расписанию: тренировочный день ≠ день отдыха
- Учитывает конкретный тип активности (зал — больше белка, бег — больше углеводов)
- Можно регенерировать конкретный день

**B) Ситуативный режим (НОВОЕ):**
Кнопка "🍽 Помощь с едой" → быстрые ситуации:
```
🍽 Что случилось?

[🎂 День рождения / застолье]
[🛒 Я в магазине]
[🍕 Хочу заказать еду]
[🏃 Перед тренировкой]
[😴 Поздно, хочу есть]
[💬 Другое — напишу]
```

**Пример: "День рождения"**
```
🎂 На дне рождения? Без проблем!

Стратегия:
1. Не голодай весь день "впрок" — это приведёт к перееданию
2. Ешь белок первым (мясо, рыба) — насыщает
3. Один кусок торта ≈ 350 ккал — это нормально
4. Алкоголь: 1-2 бокала вина (200 ккал), избегай коктейлей (500+ ккал)

📊 Твой дневной лимит: 2200 ккал
Если съешь ~500 "лишних" — завтра просто обычный день, не надо компенсировать.

📚 Источник: Harvard Healthy Eating — "Flexible dieting reduces binge episodes by 40%"

[✅ Понял] [💬 Ещё вопрос]
```

**Пример: "Я в магазине"**
```
🛒 Что покупаешь?

[🥩 Мясо/рыба] [🥛 Молочка] [🍞 Хлеб/крупы]
[🥦 Овощи/фрукты] [🍫 Перекус] [💬 Что-то конкретное]

→ Выбрал "Перекус"
→ Бот:

🍫 Хорошие перекусы (до 200 ккал):
• Греческий йогурт + орехи (15г белка)
• Протеиновый батончик (смотри чтобы >20г белка, <5г сахара)
• Творог 5% + ягоды
• Сыр + цельнозерновые хлебцы

❌ Плохой выбор: мюсли-батончики (там 30г сахара), "фитнес"-хлопья

📚 NSCA: белковый перекус между приёмами пищи улучшает синтез мышечного белка на 25%
```

### 5. Техника с объяснениями + RAG на виду

**Концепция:** Каждое упражнение в плане — не просто название, а мини-карточка с техникой.

**Формат карточки упражнения в плане:**
```
1. Жим штанги лёжа — 82.5кг × 5 × 4 (RPE 8)

💡 На что смотреть:
• Лопатки сведены и прижаты к скамье
• Гриф опускается на уровень сосков
• Стопы упираются в пол, ягодицы на скамье

⚠️ Частая ошибка: "мост" — чрезмерный прогиб поясницы.
Допустим небольшой естественный прогиб.

📚 NSCA Basics of Strength & Conditioning, Ch.12:
"Scapular retraction increases shoulder stability by 30%"

📹 Сними на видео — я проверю технику!
```

**Как это реализовать:**
- В RAG уже есть NSCA с описанием техники упражнений
- Trainer agent при генерации плана добавляет `💡 Техника` блок к каждому упражнению
- В конце каждого — call-to-action на видео-анализ
- Sources показываются автоматически из RAG-ответа

**Ценность RAG на виду:**
В КАЖДОМ ответе бота — ссылка на источник:
```
📚 Источник: [название книги/статьи]
```
Это ключевой дифференциатор: "не выдумка ChatGPT, а наука".

### Value Proposition (обновлённая)

**Для** активных людей с разнообразной жизнью,
**которые** хотят тренироваться эффективно, но не хотят нанимать тренера,
**Arete** — это AI-тренер в Telegram,
**который** адаптируется к твоему реальному графику, трекает прогресс весов, и помогает с питанием в любой ситуации.

### Архитектура Arete v2 — Summary

Arete v2 расширяет текущий стек (FastAPI + PostgreSQL/pgvector + Aiogram) тремя ключевыми модулями: *Weekly Schedule* (мульти-активное расписание вместо одного `training_style`), *Exercise Log* (трекинг весов/прогресса), и *Situation Chat* (ситуативное питание через dietologist agent). Все изменения обратно совместимы — поле `training_style` сохраняется для backwards-compatibility, но перестаёт быть основным.

### 9. Implementation Notes

1. **format_user_context() становится async** — нужен db для подтягивания расписания и exercise logs. Это потребует обновления всех мест вызова (chat.py, plans.py).

2. **Exercise name normalization** — нужна функция `normalize_exercise_name("Жим лёжа") → "bench_press"`. Можно начать с простого маппинга из 20 базовых упражнений + fallback на транслитерацию.

3. **Пробный вопрос без регистрации** — endpoint `/chat/try` вызывает RAG без user context. Это уменьшает качество ответа, но зато даёт aha moment.

4. **Авто-прогрессия весов** — `suggested_weight = last_weight + step`. Step зависит от упражнения: 2.5кг для верхней части тела, 5кг для ног, 1кг для изоляции. Хранить в маппинге по exercise_name.

5. **Schedule → agent prompt** — при генерации workout_week, format_user_context должен включать полное расписание. Trainer agent видит все 7 дней и генерирует программу для каждого.

6. **Cache invalidation** — при изменении расписания (`PUT /users/{id}/schedule`) нужно инвалидировать cached_plans так же, как при изменении training_style.
